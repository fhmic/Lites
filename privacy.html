LITE — Privacy Policy

Effective date: September 22, 2026

LITE is a personal automation agent application that runs on its owner's own computer. This policy explains what data LITE accesses, how that data is used, who it is shared with, how it is stored, and how it can be deleted.

1. Who we are

LITE is developed and operated as a single-user personal application by its owner, Felix H. Michael. It is not a public-facing service, has no other users, and does not collect data from anyone other than its owner. Contact: felixh.michael@gmail.com.

2. Google user data LITE accesses

LITE requests only the following Google OAuth scopes:

  • gmail.readonly — read access to the owner's Gmail account, used to list recent inbox messages and display their content (sender, subject, date, and body) on screen when the owner asks what an email says.
  • gmail.compose — the ability to create draft replies in the owner's Gmail Drafts folder. This scope cannot send email. LITE deliberately contains no code that sends email; every reply it writes must be reviewed and sent by the owner manually.
  • calendar — read and write access to the owner's Google Calendar, used to list upcoming events and create events the owner asks for. Attendees are never added to an event without the owner's explicit prior confirmation in conversation.

3. How the data is used

  • Email content is retrieved only when the owner asks to check the inbox, read a specific email, or draft a reply, or when a scheduled inbox scan runs to summarize what is unread.
  • Email and calendar data are used solely to perform the task the owner requested — displaying inbox contents, drafting a reply, or creating a calendar event.
  • LITE does not use Google user data for advertising, profiling, analytics, model training, or any purpose other than the owner-requested tasks above.
  • LITE is a personal-use application and does not transfer Google user data to any third party for any purpose, including advertising or machine learning.

4. Third-party processing of user content

When the owner asks LITE to summarize, reply to, or act on an email or document, the relevant text is sent to a large language model API to generate the response. Depending on the configured provider, that may be Google Gemini (Google Cloud), Anthropic (Claude), or Groq. These providers process the text solely to generate LITE's response; LITE does not send them Google account credentials, tokens, or contact lists — only the message text needed for the task. Their handling of API-submitted content is governed by their own terms. No LLM provider is given the ability to read or send the owner's email; they only ever see text LITE explicitly passes to them for a requested task.

5. Storage and retention

  • Google OAuth credentials (the access/refresh token) are stored only locally on the owner's computer, in a local configuration file, and never transmitted anywhere except directly to Google's OAuth servers.
  • Email bodies, calendar data, and drafted replies are not permanently stored by LITE. Content is fetched from Google at request time, displayed, and discarded. The app keeps only small local logs of its own actions (e.g., that an inbox scan ran), not of email content.
  • Documents and presentations LITE generates are saved as local files on the owner's computer.

6. Data sharing

LITE does not sell, rent, or share Google user data with any third party. The only external transmission of user content is the LLM API request described in section 4, and it is limited to the text needed for the task the owner explicitly requested.

7. Data deletion

  • Deleting the local token file immediately revokes LITE's stored access; LITE will stop working with Google services until re-authorized.
  • Access can be revoked at any time from the owner's Google Account at myaccount.google.com/permissions, which immediately invalidates LITE's access to Gmail and Calendar.
  • Any drafts LITE created remain in the owner's own Gmail Drafts folder, under the owner's control.

8. Security

LITE runs entirely on the owner's own machine. OAuth tokens are stored in a local, non-public configuration location and are never logged, embedded in source code, or committed to version control. Communication with Google and LLM providers happens over encrypted HTTPS connections.

9. Changes to this policy

If LITE's data handling changes, this policy will be updated here with a new effective date before the change takes effect.
